# 钉钉机器人 0 → 1 完整部署指南

> 目标：在企业钉钉群里 @机器人 发一句 `1.2.3.4`，服务器防火墙自动放行，
> 机器人立刻回一张结果卡片。
>
> 全程使用 **Stream 模式**：不需要公网 IP、不需要域名、不需要备案、不需要内网穿透。

---

## 0. 前置条件

| 项目 | 要求 |
|---|---|
| 钉钉账号 | 企业员工账号（个人版账号无法创建企业内部应用） |
| 权限 | 企业管理员，或能找管理员审批应用发布 |
| 服务器 | 能访问 `api.dingtalk.com` 与 `wss-open-connection-union.dingtalk.com:443`（出网即可，无需入网） |
| 本项目 | 已执行 `start.bat` / `python run.py` 并能在浏览器打开管理台 |

> 检查出网能力：
> ```bash
> curl -I https://api.dingtalk.com
> ```
> 返回 404/401 都算通（说明 TLS 与 DNS 正常）。

---

## 1. 创建企业内部应用

1. 浏览器打开钉钉开发者后台：<https://open-dev.dingtalk.com/>
2. 顶部选择正确的**组织**（右上角组织名，别选错企业）。
3. 左侧菜单 **应用开发 → 企业内部应用 → 钉钉应用** → 右上角 **创建应用**。
4. 填写：
   - 应用名称：`动态云防火墙`（群里显示的机器人名可后续单独改）
   - 应用描述：`IP 放行助手`
   - 应用图标：随便传一张 240×240 的图
5. 点击 **保存**，进入应用详情页。

✅ 检查点：应用详情页能看到「凭证与基础信息」卡片。

---

## 2. 获取四个凭证并对应到本项目

在 **应用详情 → 凭证与基础信息** 中复制以下值：

| 钉钉后台字段 | 本项目配置项 | 说明 |
|---|---|---|
| **Client ID**（原 AppKey / SuiteKey） | `Client ID` | 形如 `dingxxxxxxxxxxxx` |
| **Client Secret**（原 AppSecret / SuiteSecret） | `Client Secret` | 只显示一次，务必立即保存 |
| **App ID** | `App ID` | UUID 形式，如 `a1b2c3d4-e5f6-...` |
| **AgentId**（应用信息里） | `AgentId` | 纯数字，如 `5107578287` |

> **AgentId 在哪？** 部分版本在「凭证与基础信息」页底部，或「应用信息 → 基础信息」中。

填入管理台：**钉钉机器人 → 应用凭证 → 保存钉钉配置**。

⚠️ 安全提示：`Client Secret` 等于应用密码，泄露后任何人可冒用你的机器人发消息。
本项目把它存进 `data/app.db`（SQLite），并在页面上打码显示；不要把它提交到 Git。

---

## 3. 添加「机器人」能力并选择 Stream 模式

1. 应用详情页 → **应用能力 → 添加应用能力** → 选择 **机器人** → 添加。
2. 在机器人配置页填写：
   - **机器人名称**：`IP放行助手`
   - **机器人头像**：上传
   - **消息接收模式**：⭐ 选择 **Stream 模式**（关键！）
3. 保存。

> 两种模式的区别：
>
> | | Stream 模式 | HTTP 回调模式 |
> |---|---|---|
> | 公网 IP / 域名 | 不需要 | 必须公网可达 |
> | 内网穿透 | 不需要 | 需要 frp / ngrok |
> | 本项目配置 | `mode = stream`（默认） | `mode = callback`，并填回调地址 |
> | 稳定性 | 长连接自动重连 | 依赖公网链路 |
>
> **建议永远用 Stream 模式。** 本项目会自动建立并维护这条长连接。

如果坚持用 HTTP 回调：

1. 机器人配置里选 **HTTP 回调**，回调地址填：
   `https://你的域名/dingtalk/callback`
2. 复制钉钉给出的 **Token**（和可选 AES Key），填入管理台
   `钉钉机器人 → 访问控制` 上方的 `callback_token`（在配置文件中为 `dingtalk.callback_token`）。
3. 本地调试可用 `cloudflared tunnel --url http://127.0.0.1:5050` 临时拿到公网地址。

---

## 4. 申请接口权限

进入 **权限管理**，搜索并申请（企业内部机器人通常已默认包含发送消息权限）：

| 权限点 | 用途 |
|---|---|
| 机器人发送消息（`Robot.Message.Send` 或 `qyapi_robot_sendmsg`） | 主动向群/人推送消息 |
| 企业内机器人发送消息 | Stream 模式回执 |

申请后状态为「已开通」即可。若只做「被动回复」（用户 @ 后回卡片），
其实不需要额外权限 —— 被动回复走 `sessionWebhook`，只有**主动推送**（定时报告）
才需要上面的权限。

✅ 检查点：权限列表里相关项显示「已开通」。

---

## 5. 发布应用（最容易卡住的一步）

1. 左侧 **版本管理与发布** → **创建新版本**。
2. 填写版本号（如 `1.0.0`）、更新说明。
3. **可见范围**：选择需要使用机器人的部门/全员。⚠️ 范围外的人看不到这个机器人。
4. 保存 → **发布**。
5. 等待**企业管理员审批**（若是自己就是管理员，直接通过）。
6. 状态变为 **已发布** 才算成功。

✅ 检查点：应用列表里状态是「已发布」，而不是「开发中」。

---

## 6. 把机器人添加进群

1. 打开目标钉钉群 → 右上角 **群设置**（⋯）→ **机器人** → **添加机器人**。
2. 在列表里找到你的企业应用机器人（名字是第 3 步设置的），添加。
3. 完成后群里会出现一条「机器人已添加」的提示。

> 找不到机器人？99% 是第 5 步的**可见范围**没包含你自己，或应用未发布成功。

---

## 7. 在本项目里验证连通性

1. 打开管理台 → **钉钉机器人** 页。
2. 确认「长连接状态」显示 **在线**。
   - 若显示「离线」，看下方红字原因，常见为 `缺少 Client ID / Client Secret`。
3. 点 **测试连接** → 提示「凭证有效」说明 AccessToken 获取成功。
4. 回到页面顶部「已处理消息」，进群 @机器人 发一条 `帮助`。
   - 状态数字 +1 且机器人回复了指令卡片 = 全链路打通。

> 也可在 **日志与记录 → 机器人指令记录** 里看到每条消息的解析结果，
> 包括 `conversation_id`（后面主动推送要用）。

---

## 8. 拿到 openConversationId（主动推送 / 每日报告用）

被动回复不需要它，但「每日巡检报告」「Webhook 放行通知」「测试发送」需要。

> **一句话原理**：`openConversationId` 是群会话的唯一 ID（形如 `cidXXXXXX==`），
> 只能由钉钉在**机器人收到群消息时**下发。所以你没法凭空手填，必须先让机器人在群里说上话。

**方法 A（最省事，推荐）**：在群里 @机器人 发一条 `帮助`，等它回卡片；
然后到管理台 **钉钉机器人 → 测试发送 → 点「自动获取」**，会直接列出机器人收到过消息的群，
点一下自动填入。

**方法 B**：打开 **日志与记录 → 机器人指令记录**，那条记录的「群」列就是 `conversation_id`，手动复制。

**方法 C**：看服务端日志 `logs/app.log`，Stream 客户端会打印消息体里的 `conversationId`。

拿到后填到 **钉钉机器人 → 通知群 ConversationId**，并打开「Webhook 放行后推送群通知」；
「测试发送」的目标会话留空时会自动使用这个通知群。

> 发不出去的两个常见原因：
> 1. 机器人不在那个群里 → 先把机器人加进群；
> 2. 应用没有「机器人发送消息」权限，或应用版本改了没重新发布。

## 9. 指令规范（发什么机器人认什么）

| 群里发送 | 效果 |
|---|---|
| `1.2.3.4` | 放行该 IP **全部端口**，默认 24 小时后自动回收 |
| `1.2.3.4 22` | 仅放行 TCP 22 |
| `1.2.3.4:22` | 同上（冒号写法也行） |
| `1.2.3.4 22,80,443` | 多个端口 |
| `1.2.3.4 8000-9000` | 端口段 |
| `1.2.3.4 53 udp` | 指定 UDP 协议 |
| `1.2.3.4 1.2.3.5 22` | 多个 IP 同一端口 |
| `放行 1.2.3.4 22` | 带动词，等价 |
| `删除 1.2.3.4` | 撤销该 IP 的放行 |
| `列表` | 查看当前生效规则 |
| `状态` | 查看系统概览 |
| `我的IP` | 查询出口 IP（Stream 模式拿不到，会提示直接发 IP） |
| `帮助` | 指令菜单 |

**动作链路**：钉钉 → Stream 长连接 → 指令解析 → 阿里云 SWAS 防火墙 API →
结果写库 → `sessionWebhook` 回卡片。

## 10. 排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| **页面显示"已连接"，但群里 @ 没反应** | 最常见：钉钉没把消息推给这个应用 | 点「诊断」看「收到过原始消息帧」是否为 0，为 0 说明消息根本没到。按下面 4 条逐一确认 |
| 诊断里"长连接已建立"通过但"收到过原始消息帧"= 0 | ① @ 的不是本应用的机器人；② 消息接收模式不是 Stream；③ 应用未发布；④ 账号不在可见范围 | 见下方专项排查 |
| 页面显示"未连接" | 凭证错 / 网络出不去 | 点「诊断」，看 AccessToken 与 last_error |
| 提示 `invalid appKey or appSecret` | Client ID/Secret 填错，或复制时带空格 | 重新复制，注意不要带首尾空格 |
| 群里 @ 机器人没反应 | 没有 @、或机器人未进群、或 `require_at` 打开但没真正 at | 确认 @ 选中了机器人头像；查看「机器人指令记录」是否有该消息 |
| 记录里有消息但没有回复 | `sessionWebhook` 过期（>1.5h 的旧消息） | 重新发一条新消息 |
| 回复「未授权的会话」 | 配了群白名单但不匹配 | 清空白名单，或把日志里的 conversation_id 加进去 |
| 回复「没有可用的阿里云实例」 | 未在「系统设置」添加实例 | 添加实例 ID（控制台实例详情页可复制） |
| 回复「云端创建失败: Forbidden.RAM」 | AccessKey 权限不足 | 给 RAM 用户授权 `AliyunSWASFullAccess` |
| 连接反复断开 | 服务器出网被限制/代理拦截 | 放行 `api.dingtalk.com`、`wss-open-connection-union.dingtalk.com:443` |
| 应用改了配置但没生效 | 修改后需重新发布版本 | 每次都「创建新版本 → 发布」 |

### 专项排查：连上了但收不到消息（frames = 0）

长连接能建立，只能证明 **Client ID / Secret 有效**，不代表消息会推给你。按顺序核对：

1. **@ 的是哪个机器人**
   群设置 → 机器人，点开那个机器人看它的「来源应用」。如果不是你刚创建的应用，
   说明群里装的是别的机器人（比如自定义 Webhook 机器人），删掉重加。

2. **消息接收模式是不是 Stream**
   开发者后台 → 应用 → 应用能力 → 机器人 → 配置，「消息接收模式」必须是 **Stream 模式**。
   选了 HTTP 回调，消息会打到公网地址，Stream 这边永远是 0 帧。

3. **应用发布了没有**
   「版本管理与发布」里必须是**已发布**状态。开发中的版本不会给 Stream 推消息。
   ⚠️ 改完机器人配置后要**重新创建版本并发布**才生效。

4. **可见范围包含你吗**
   版本详情里的可见范围要包含你所在部门，否则机器人在群里也不响应。

5. **@ 的方式对吗**
   必须从输入框的 @ 列表里选中机器人（变蓝），只敲文字"@IP放行助手"不算 @。

> 排查完在管理台点「诊断」，观察「收到过原始消息帧」是否从 0 变成 ≥1。
> 帧数动了但消息数还是 0，就看 `logs/app.log` 里的 `Stream 收到帧 ...` 那行的 topic。

查看实时日志：

```bash
tail -f logs/app.log
```

## 11. 安全建议

1. **改默认密码**：管理台默认 `admin/admin123`，登录后立即在「系统设置」修改。
2. **限制群**：只在需要的群里添加机器人；用「允许的群 ConversationId」白名单锁死。
3. **限制人**：把关键操作人 userId 加进「允许的成员」。
4. **设默认 TTL**：把 `default_ttl_minutes` 设为 `1440`（24h）甚至 `60`，
   规则到期自动回收，避免长期全网段放行。
5. **最小权限 AccessKey**：为 RAM 子账号只授予 `AliyunSWASFullAccess`，
   绝不要用主账号 AK。
6. **不要公网裸奔**：管理台监听 `0.0.0.0` 时，务必用安全组/反向代理限制来源 IP，
   或改为只监听 `127.0.0.1` 后用 SSH 隧道访问。
