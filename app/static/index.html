纳管实例

规则策略

公网 IP 自动放行

定时把当前公网 IP 同步进防火墙，动态 IP 不掉线
任务「公网 IP 自动放行」默认每小时执行（可在定时任务页改）。IP 没变就顺延有效期， 变了就自动替换规则，并推送一条「IP 已跟随」的钉钉通知。 这样生成的规则自带「自动续期（跟随新 IP）」，两次任务之间到期也不会被清理掉。 若 NAS / 主机夜间会自动关机，开机后 15 秒内会自动补跑当天错过的那一次。 想彻底不过期就填 -1（永久放行，不再参与到期回收）。 若你用固定 IP 放行，可在「规则」编辑里把续期方式改成「原 IP 续期」。
动态 IP + 永久放行：永久只是不再按到期时间回收，IP 跟随仍由本任务负责。 但永久规则没有到期点，也就少了「到期时自动跟随」这条兜底，只剩本任务一条路—— 所以「永久 + 每小时检查」是动态 IP 最稳的组合：关机多久都不怕丢规则，IP 一变最多个把小时跟上。 同 IP 时任务只更新本地记录，不调用云端接口，开销可以忽略。

可用占位符：{action} {ip} {port} {protocol} {instance} {actor} {source} {expire} {tag} {detail} {time}

公网 IP 自动放行

家庭宽带 / 动态 IP / NAS 穿透场景的核心功能

开启后，定时任务 sync_public_ip 会按计划探测本机当前公网 IP，并与 来源=public_ip 的规则比对：

  • 还没放过这个 IP → 按设置的端口 / 协议 / 有效期新建规则；
  • IP 没变 → 只刷新有效期，不重复创建，也不调用云端接口；
  • IP 变了 → 删除旧 IP 的规则，按新 IP 重建，并推送一条「公网 IP 已自动跟随」通知。
有效期取值含义
正数（分钟）直接使用该有效期
0跟随「规则策略 → 默认有效期」
-1永久放行：不写到期时间、永不参与过期回收

动态 IP + 长期放行（NAS 穿透）推荐组合：有效期填 -1，计划保持默认的 每小时。永久保证「关机多久都不丢规则」，每小时检查保证「IP 一变最多个把小时跟上」。 而永久规则没有到期点，也就没有「到期时自动跟随」那条兜底，所以别把计划调得太稀。

主机夜间会自动关机？调度器启动后 15 秒会补跑当天错过的日级任务 （每日备份、日志清理等），日志里记为「启动补跑任务」。每小时任务开机后自然会在下一个整点执行。

Webhook 与命令行

给 ddns-go、路由器、CI 脚本调用
curl -X POST http://你的地址:5050/webhook/ip-change \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: 系统设置里填的密钥" \
  -d '{"ipv4":"1.2.3.4","ports":"ALL","ttl_minutes":1440,"domain":"home.ddns.net"}'

支持字段：ip / ipv4 / ipv6 / ports / protocol / ttl_minutes / domain。

没配密钥时，该接口只接受本机回环调用（网页「一键放行」走的就是这条路）， 外部请求一律 403。要让 ddns-go 调用，必须先在「系统设置 → Webhook」设置密钥； 若开启了 Webhook 二次验证，还要带 X-2FA-Code: 123456， 或在白名单网段里让该来源免验证。

二次验证（2FA）

TOTP 动态口令，与口令 / Token 叠加
  1. 「系统设置 → 二次验证」点「生成密钥」，页面出现二维码；
  2. 用 Google Authenticator / 微软 Authenticator / 1Password 扫码绑定；
  3. 在「验证」框输入客户端显示的 6 位数字，确认密钥配对成功；
  4. 打开总开关，再按需勾选作用范围：网页登录、Webhook、钉钉机器人；
  5. 保存后立即生效，网页登录会多出一个动态口令输入框。

两个附加策略：钉钉全指令验证（默认只验放行 / 删除 / 续期）、 Webhook 内网免验证（含自定义白名单网段），避免本机调用被自己拦住。

密钥属于敏感信息，界面上只显示后 4 位；换手机前请先备份密钥或重新生成。

计划可在「定时任务」页逐条修改，保存后调度器热重载，无需重启。 进程停机期间错过的日级任务，会在启动 15 秒后自动补跑一次。

群晖 / NAS 部署要点

Docker 单进程，数据必须落在挂载目录
  • 必须单实例：调度器与钉钉长连接都是进程内单例，不要起多个副本。
  • 持久化：./data（数据库 + 配置镜像）和 ./logs 必须挂载出来， 否则重建镜像会丢规则与凭证。
  • 更新代码：源码是打进镜像的，改完要「重新构建」而不是只「重启」； 重建前不要用整包覆盖 data/。
  • 夜间自动关机：日级任务会在开机后补跑；把公网 IP 任务保持每小时，开机最多等一小时。
  • 端口：默认 5050，容器内监听 0.0.0.0，映射到宿主机即可。

常见问题

先看这几条，能省掉大部分排查
刚放行的 IP，规则列表里看不到？

检查列表上方的状态筛选（默认只看「在用」）。被删除的规则是软删除，切到「已删除」才能看到， 可在那里恢复。

群里斯 @机器人 没反应？

依次确认：机器人开关已开、长连接状态正常（顶栏「机器人」徽标）、确实 @了机器人、 发送人在允许名单内（留空表示不限制）、群在允许名单内。

内网穿透突然断了？

多半是公网 IP 变了。看「日志与记录」里有没有「公网 IP 已自动跟随」，或者钉钉有没有收到 IP 变化通知； 也可以在「阿里云防火墙」页对比云端规则与当前公网 IP。

凌晨的定时任务没执行？

先看主机在那段时间是否开机。停机期间错过的日级任务会在启动后自动补跑； 每小时任务则在开机后的第一个整点执行。

忘记后台口令了怎么办？

停掉服务，在项目目录执行下面的脚本把口令重置为 admin123，重启后用 admin / admin123 登录，系统会强制要求改密。其余配置不会丢。

python -c "
import json, sqlite3
c = sqlite3.connect('data/app.db')
v = c.execute(\"SELECT value FROM settings WHERE key='app_settings'\").fetchone()[0]
d = json.loads(v); d['server']['admin_password'] = 'admin123'
c.execute(\"UPDATE settings SET value=? WHERE key='app_settings'\", (json.dumps(d, ensure_ascii=False),))
c.commit(); print('ok')"
